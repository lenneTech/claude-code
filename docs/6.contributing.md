The repository is public. Customer names, internal hosts, tokens, `.env` files and local user paths never belong in
it; the plugins ship anonymized examples only.

## Setup

```bash
git clone git@github.com:lenneTech/claude-code.git
cd claude-code
scripts/install-hooks.sh
```

`install-hooks.sh` turns on the pre-commit and pre-push hooks, which run `scripts/scan-secrets.sh`.
`.github/workflows/secrets-guard.yml` repeats the scan in CI.

## Checks

- `claude plugin validate plugins/<plugin>` validates a plugin.
- The plugin CI (`.github/workflows/plugin-ci.yml`) also runs the script tests, the context budgets and the rule
  invariants.
- [CLAUDE.md](https://github.com/lenneTech/claude-code/blob/main/CLAUDE.md) holds the conventions for plugin
  elements, the documentation cache under `.claude/docs-cache/` and the `/optimize` command for this repository.
  Claude Code reads it when you work in the repository.

## Docs

The pages of this section live in `docs/` and are changed in the same pull request as the plugin. The convention is
on [Writing docs](https://docs.lennetech.app/contributing). The architecture decisions of the repository are in
`docs/adr/` and are not published.

## Release

Commit the content first, then run:

```bash
bun run version:patch "<description>"   # or version:minor / version:major
```

The script raises the version in `package.json`, `.claude-plugin/marketplace.json` and every `plugin.json`, commits
only that bump (it stops when the index already holds staged changes), tags `v<version>` and pushes branch and tag.
Only repository admins can push to `main`: a ruleset sends every other change through a pull request with a green
secret guard, so contributors open a pull request and the maintainer releases.
Installed plugins pick the release up through their [automatic updates](./1.installation.md#updates).
