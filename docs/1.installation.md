## Requirements

- [Claude Code](https://code.claude.com/docs)
- Node.js 22 or newer for the plugin scripts
- `jq`, which the hooks use to read their input
- Google Chrome (or Chrome Canary) for browser checks through the Chrome DevTools MCP server and for the `lt-tools`
  website comparison
- The [lt CLI](https://github.com/lenneTech/cli) for the recommended installation and the automatic permission setup

## Through the lt CLI (recommended)

```bash
npm i -g @lenne.tech/cli

lt claude plugins                  # install or update every plugin of the marketplace
lt claude plugins lt-dev lt-tools  # install or update the named plugins
```

The CLI adds and refreshes the marketplace, installs or updates the plugins, and copies the Bash permissions from
`plugins/lt-dev/permissions.json` into `~/.claude/settings.json` (see [Permissions](./2.permissions.md)).

Without a plugin name it also installs the recommended `typescript-lsp` plugin from the official Claude Code
marketplace, which gives Claude a TypeScript language server. To install it alone: `lt claude plugins typescript-lsp`.

## Manual

In a Claude Code session:

```text
/plugin marketplace add lenneTech/claude-code
/plugin install lt-dev@lenne-tech
```

A manual installation sets no permissions. To get the same rules, copy the `pattern` values from
[`plugins/lt-dev/permissions.json`](https://github.com/lenneTech/claude-code/blob/main/plugins/lt-dev/permissions.json)
into the `permissions.allow` array of `~/.claude/settings.json`.

## Companion plugin for Figma

The Figma commands of `lt-dev` (`/lt-dev:frontend:figma-*` and the `--figma=<url>` flag of the ticket commands) need
the official `figma` plugin:

```bash
claude plugin install figma@claude-plugins-official
```

Everything else works without it.

## Updates

You do not have to update by hand. At session start `lt-dev` runs `lt claude plugins` in the background, at most
once an hour. A session that stays open for days checks every ten minutes: when the last update on the machine is
twelve hours old it starts one, and when a newer plugin version is installed it reloads its plugins on its own once
the running turn has ended. A session that started right after an update shows which plugins changed.

If a running session does not pick up a new version, run `/reload-plugins` in it.

## Shell shortcuts (optional)

```bash
lt claude shortcuts
```

The command detects your shell (zsh or bash) and adds these aliases to its configuration file:

| Alias | Runs | Purpose |
|---|---|---|
| `c` | `claude --dangerously-skip-permissions` | Start a new session |
| `cc` | `claude --dangerously-skip-permissions --continue` | Continue the last session |
| `cr` | `claude --dangerously-skip-permissions --resume` | Pick a previous session and resume it |
| `cf` | `LT_PLUGIN_HOOKS_SKIP=1 claude --dangerously-skip-permissions` | Start without the lenne.tech project detection hooks |

::warning
`--dangerously-skip-permissions` lets Claude run every command without asking, including destructive ones. Use the
aliases only if you accept that risk, and keep your work committed or backed up. For everyday work the
[auto permission mode](./2.permissions.md) is the safer choice.
::

## IDE integration

Claude Code has extensions for [VS Code](https://code.claude.com/docs/en/vs-code) and
[JetBrains IDEs](https://code.claude.com/docs/en/jetbrains) (WebStorm, IntelliJ and others). The plugins work the same
way in the terminal and in the IDE.

## Check the installation

```bash
claude --version
lt --version
```

In a Claude Code session, `/plugin` lists the installed plugins, and typing `/lt-dev:` lists the commands of
`lt-dev`.
