Claude Code sessions on one machine can list and message each other. `lt-dev` uses that sparingly and in a fixed
order.

## Cheapest channel first

Linear stays the claim protocol for tickets and Git for branches, because both are free to read and stay true after
a session ends. `ListAgents` adds who is alive right now. Only what none of those carry goes over a message, since a
delivered message costs the receiving session a full prompt in the middle of its work.

Seven occasions justify a message. Three protect a peer from doing the wrong thing (`LANDED`, `CLAIM`, `CONFLICT`),
two save it work (`SOLVED`, `READY`), one asks for something it answers cheaply (`ASK`), and one asks who wrote a
change and why (`ORIGIN`). Progress reports, "I am finished" and anything readable in the repository are not on the
list.

## A diff says what changed, never why

When a session finds uncommitted changes it did not write, it does not review, commit or resolve them as if they
were its own. `scripts/change-provenance.sh` separates what this session wrote from what it found and names the live
sessions that could explain the difference, so `review`, `git:ship`, `dev-submit`, `debug` and the rebase ask one
targeted question first.

## What has to outlive a session

Messages are not history: a session started later never sees them. `scripts/peer-ledger.sh` keeps open claims on
cross-cutting work and diagnoses worth keeping per repository under `~/.claude/lt-dev/peer-ledger/`, never inside a
project. A claim is bound to its session's process, so the claim of a crashed session reads as stale and free to
take.

## Commands

| Command | What it does |
|---|---|
| `/lt-dev:peers` | Live sessions, open claims, recorded diagnoses and foreign uncommitted changes in one read-only report |
| `/lt-dev:briefing` | Re-checks every open thread of the session against its source, finishes what Claude can still do, then lists what is left for you |
| `/lt-dev:desktop-sessions` | Brings Claude Desktop sessions of another Claude account into the active one |

At session start a hook reports how many other sessions are live and how many of them work in the same repository.

## Who decides

Who takes which ticket, who fixes a shared finding and who waits for whom are settled between the sessions without a
prompt. Scope, priority, risk, anything destructive, anything a permission prompt would cover, and a contested claim
that one exchange did not settle always come to you.

## One setup step

With `crossSessionInbound` unset, Claude Code delivers a message between two sessions only when their permission
modes match. Otherwise it shows an approval dialog that expires after five minutes, which is how coordination fails
on unattended sessions. Set `crossSessionInbound: "accept"` in your user settings (or in `/config` → "Messages from
your other sessions").
