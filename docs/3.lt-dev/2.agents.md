An agent is a sub-session with its own instructions and tools. You rarely start one yourself: the commands start
them, often several in parallel, and collect their reports. You can also ask for one directly, for example
"let the security-reviewer look at this branch". Each agent is a Markdown file under
[`plugins/lt-dev/agents/`](https://github.com/lenneTech/claude-code/tree/main/plugins/lt-dev/agents).

## Planning and implementation

| Agent | What it does |
|---|---|
| `architect` | Plans a feature without writing code: a phased blueprint with file paths, data models, REST contracts, permissions and frontend state |
| `backend-dev` | Implements backend features with tests in NestJS and `@lenne.tech/nest-server`, under the stack's security rules |
| `frontend-dev` | Implements frontend features in Nuxt 4 and Vue with strict TypeScript and SSR-safe patterns, and checks the result in the browser |
| `devops` | Creates and changes Dockerfiles, docker-compose, CI/CD pipelines, environment and secret handling |
| `ticket-analyst` | Analyzes one Linear ticket read-only for the question round of `ticket-batch` |
| `adr-maintainer` | Writes the repository's ADR log: reconstructs past decisions, records new ones, lints the log |

## Review

`/lt-dev:review` runs the domain reviewers in parallel and keeps only proven Critical and High findings.

| Agent | What it reviews |
|---|---|
| `code-reviewer` | A change set in one pass: runs `check` and fixes every error, then grades content, security, quality, tests, docs and formatting |
| `backend-reviewer` | Backend changes against the `backend-dev` conventions |
| `frontend-reviewer` | Nuxt and Vue code against the `frontend-dev` conventions |
| `security-reviewer` | OWASP review of backend and frontend: permissions, injection, XSS, CSRF, auth, dependency CVEs, Docker and secrets |
| `test-reviewer` | Test quality: coverage gaps, assertions, isolation, API-first tests, least-privilege permission tests |
| `docs-reviewer` | README, JSDoc, migration guides and comments of a change |
| `ux-reviewer` | UX patterns in code and in the browser: loading, empty and error states, feedback, forms, destructive actions |
| `a11y-reviewer` | Accessibility, semantic HTML and SEO, by static analysis and Lighthouse |
| `performance-reviewer` | Bundle, database queries, memory, payloads and caching, optionally with k6 load tests |
| `devops-reviewer` | Docker, docker-compose, CI/CD and secret handling, without changing them |

## Updates and vendor mode

| Agent | What it does |
|---|---|
| `nest-server-updater` | Updates the `@lenne.tech/nest-server` npm package, applying the migration guides major by major |
| `nest-server-core-updater` | Adopts upstream nest-server changes into a vendored core, hunk by hunk against local patches |
| `nest-server-core-contributor` | Finds substantial local changes in a vendored nest-server core and prepares upstream PR drafts |
| `nuxt-extensions-core-updater` | Adopts upstream nuxt-extensions changes into a vendored frontend core |
| `nuxt-extensions-core-contributor` | Prepares upstream PR drafts from local changes in a vendored nuxt-extensions core |
| `ng-base-core-updater` | Syncs upstream ng-base into a vendored Angular core |
| `ng-base-core-contributor` | Prepares upstream PR drafts from local changes in a vendored ng-base core |
| `vendor-mode-converter` | Converts an API from npm mode to vendor mode |
| `vendor-mode-converter-frontend` | Converts a Nuxt frontend from npm mode to vendor mode |
| `fullstack-updater` | Updates a fullstack monorepo to the current starters, after you approve the plan |
| `npm-package-maintainer` | Updates, audits and cleans up npm dependencies |

## Other

| Agent | What it does |
|---|---|
| `branch-rebaser` | Rebases a feature branch onto the development branch, resolves conflicts, lints, tests and reviews |
| `production-readiness-orchestrator` | Runs the test, load-test, audit and CI phases of `/lt-dev:production-ready` |
