A command is an action you start yourself by typing `/lt-dev:<name>` in a Claude Code session. Most commands take
arguments; the hint after the name in Claude Code's command menu shows which. Each command is a Markdown file under
[`plugins/lt-dev/commands/`](https://github.com/lenneTech/claude-code/tree/main/plugins/lt-dev/commands), which
holds the full instructions.

## Tickets and planning

| Command | What it does |
|---|---|
| `/lt-dev:ticket-cycle` | The whole ticket lifecycle in one command: pick or take a ticket, settle decisions, implement test-driven, review, check in the browser, get your approval, then MR/PR, CI, merge and Linear handoff. `--autopilot` runs it without questions |
| `/lt-dev:ticket-batch` | Works every ticket of a Linear project that is in Open or Fix needed and yours or unassigned: all questions first, then the tickets one after another, one test package for all |
| `/lt-dev:take-ticket` | Picks the next Linear ticket (Fix needed and Open, by priority) or takes an explicit ID, then branches, implements test-driven, runs all tests and `check`, and reports a review-ready summary |
| `/lt-dev:resolve-ticket` | Resolves one Linear ticket or story file test-driven, without auto-pick |
| `/lt-dev:dev-submit` | Creates the MR/PR, posts the Linear comment and moves the ticket to Dev Review |
| `/lt-dev:create-ticket` | Creates a Linear ticket (story, task or bug) in a guided workflow |
| `/lt-dev:create-story` | Creates a user story for a test-driven implementation |
| `/lt-dev:create-task` | Creates a technical task |
| `/lt-dev:create-bug` | Creates a bug report |
| `/lt-dev:spec-to-tasks` | Turns a PRD, a specification or a Linear ticket into structured, prioritized tasks |
| `/lt-dev:interview` | Asks about a plan or specification until every open decision is settled, then writes the outcome back into the plan |
| `/lt-dev:linear-comment` | Posts a short, testable comment on a Linear issue: plain-language summary and test steps, technical detail in an attached document |
| `/lt-dev:adr` | Sets up and maintains the repository's Architecture Decision Records (`docs/adr/`): reconstruct, check a ticket or plan, record a decision, lint |

## Quality

| Command | What it does |
|---|---|
| `/lt-dev:review` | Reviews what the current diff changed. Reports only proven Critical and High defects, plus security risks with a demonstrated attack path, and fixes them |
| `/lt-dev:check` | Runs the project's `check` script in every sub-project and fixes until it is green, audit findings included |
| `/lt-dev:debug` | Debugging with competing hypotheses: several investigators challenge each other until the root cause is found (needs Agent Teams) |
| `/lt-dev:production-ready` | Seven phases before a go-live: full test suite without skips, flow coverage, k6 load test, eight-pillar audit, review, `check` and the CI pipeline run locally |
| `/lt-dev:refactor-frontend` | Refactors a whole frontend to the `frontend-dev` guidelines with parallel agent teams |

## Git

| Command | What it does |
|---|---|
| `/lt-dev:git:ship` | Ships a feature branch into `dev`, promotes a base branch upward, or lands a hotfix: commit, rebase, tests, `check`, MR/PR, Linear handoff, CI wait, merge, cleanup |
| `/lt-dev:git:create-request` | Creates a merge request (GitLab) or pull request (GitHub) from the current branch |
| `/lt-dev:git:commit-message` | Suggests a commit message with alternatives |
| `/lt-dev:git:mr-description` | Writes a merge request description, optionally straight to the clipboard |
| `/lt-dev:git:rebase` | Rebases the current branch onto `dev`, with conflict resolution, linting, tests and review |
| `/lt-dev:git:rebase-mrs` | Rebases several MRs/PRs onto `dev` in one run, then commits and force-pushes |
| `/lt-dev:git:audit-requests` | Lists the open PRs and MRs of a repository, or of all repositories in the sub-directories, and says which are still needed |

## Backend (nest-server)

| Command | What it does |
|---|---|
| `/lt-dev:backend:update-nest-server` | Updates `@lenne.tech/nest-server` with the migration guides; in a vendored project it syncs the core instead |
| `/lt-dev:backend:update-nest-server-core` | Syncs a vendored nest-server core (`src/core/`) from upstream |
| `/lt-dev:backend:contribute-nest-server-core` | Prepares local core changes as upstream pull requests for nest-server |
| `/lt-dev:backend:convert-to-vendor` | Converts an API from npm mode to vendor mode and applies the migrations of the version gap |
| `/lt-dev:backend:convert-to-npm` | Converts a vendored API back to npm mode |
| `/lt-dev:backend:test-generate` | Writes tests for the current changes |
| `/lt-dev:backend:code-cleanup` | Cleans up backend code |
| `/lt-dev:backend:sec-review` | Security review of the current changes |
| `/lt-dev:backend:sec-audit` | OWASP security audit of dependencies, configuration and code |
| `/lt-dev:backend:ai-model-review` | Recurring review of the project's AI models: shutdowns, capabilities, measurement against the project's own benchmark |

## Frontend

| Command | What it does |
|---|---|
| `/lt-dev:frontend:update-nuxt-extensions-core` | Syncs a vendored nuxt-extensions core (`app/core/`) from upstream |
| `/lt-dev:frontend:contribute-nuxt-extensions-core` | Prepares local core changes as upstream pull requests for nuxt-extensions |
| `/lt-dev:frontend:update-ng-base-core` | Syncs a vendored ng-base core (`src/core/`) of an Angular app from upstream |
| `/lt-dev:frontend:contribute-ng-base-core` | Prepares local ng-base core changes as upstream pull request drafts |
| `/lt-dev:frontend:convert-to-vendor` | Converts a Nuxt frontend from npm mode to vendor mode |
| `/lt-dev:frontend:convert-to-npm` | Converts a vendored Nuxt frontend back to npm mode |
| `/lt-dev:frontend:env-migrate` | Moves Nuxt environment variables to the `NUXT_` prefix and maps them in `useRuntimeConfig()` |
| `/lt-dev:frontend:init-conventions` | Adds a code conventions section to the project's `CLAUDE.md` |
| `/lt-dev:frontend:figma-init` | Takes the design system from Figma (colors, spacing, radius, fonts) into the Nuxt UI and Tailwind theme |
| `/lt-dev:frontend:figma-research` | Reads the structure of a Figma file and writes the project config for `figma-to-code` |
| `/lt-dev:frontend:figma-to-code` | Builds Figma designs as Nuxt 4 pages |

The Figma commands need the [companion plugin](../1.installation.md#companion-plugin-for-figma).

## Fullstack

| Command | What it does |
|---|---|
| `/lt-dev:fullstack:update-all` | Updates backend and frontend frameworks, applies migrations, updates all packages, syncs `CLAUDE.md` and validates |
| `/lt-dev:fullstack:update` | Brings a fullstack project in line with the current nest-server-starter and nuxt-base-starter |
| `/lt-dev:fullstack:convert-to-vendor` | Converts backend and frontend to vendor mode in one run |
| `/lt-dev:fullstack:convert-to-npm` | Converts backend and frontend back to npm mode |
| `/lt-dev:fullstack:sync-claude-md` | Syncs the `CLAUDE.md` files from the starter templates into the project |
| `/lt-dev:fullstack:smoke-test` | End-to-end test of the whole stack: creates fullstack projects, checks them locally, deploys them and checks both stages online |

## Maintenance and releases

| Command | What it does |
|---|---|
| `/lt-dev:maintenance:maintain` | Full maintenance: framework updates, then npm package maintenance |
| `/lt-dev:maintenance:maintain-check` | Dry run: what an npm maintenance would change, without changing anything |
| `/lt-dev:maintenance:maintain-security` | Security-only updates for vulnerable packages |
| `/lt-dev:maintenance:maintain-pre-release` | Zero-risk patches before a release |
| `/lt-dev:maintenance:maintain-post-feature` | Dependency cleanup after a feature |
| `/lt-dev:maintenance:maintain-stack` | Maintains and releases all lt base repos in dependency order, gated by the smoke test |
| `/lt-dev:publish` | Publishes a base repo as a new version, then updates and releases the starters that depend on it |

## Sessions

| Command | What it does |
|---|---|
| `/lt-dev:briefing` | Re-checks everything this session worked on, finishes what Claude can still do, then tells you in plain words what is open and what only you can decide or do |
| `/lt-dev:peers` | Shows what other Claude Code sessions on this machine are doing, plus open claims and recorded diagnoses for this repository |
| `/lt-dev:desktop-sessions` | Brings Claude Desktop sessions of another Claude account into the active one, with their history |
