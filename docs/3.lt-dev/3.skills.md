A skill is expertise Claude loads by itself when your request or the files you work on match it. You do not call a
skill: ask for the task ("add a module for invoices", "the pipeline fails, check it locally") and Claude picks the
skill. Commands load the skills they need as well. Each skill is a folder under
[`plugins/lt-dev/skills/`](https://github.com/lenneTech/claude-code/tree/main/plugins/lt-dev/skills) with a
`SKILL.md` and reference files.

Some skills also react to German keywords, for example "Pakete aktualisieren", "im Browser prüfen" or
"Festplatte voll".

## Building in the stack

| Skill | When it is used |
|---|---|
| `generating-nest-servers` | All NestJS and `@lenne.tech/nest-server` work: modules, services, controllers, models, DTOs, `@Roles`/`@Restricted`, API tests |
| `developing-lt-frontend` | All Nuxt 4 and Vue work: pages, components, composables, Valibot forms, generated API types, Better Auth, Playwright |
| `developing-lt-angular-frontend` | Angular 22 work on `@lenne.tech/ng-base` |
| `building-stories-with-tdd` | Test-driven development of a story: the story test first, then the implementation until every test passes |
| `using-lt-cli` | Any `lt` command: `lt fullstack`, `lt server`, `lt dev`, `lt deployment`, npm and vendor mode |
| `checking-upstream-first` | Before a workaround around a framework is built: checks whether the current version or a base repo already solves it |
| `general-frontend-security` | XSS, CSRF, CSP, secure cookies and security headers |

## Running and checking

| Skill | When it is used |
|---|---|
| `running-check-script` | Whenever work has to prove it runs: `check` in every sub-project, fixed until green |
| `managing-dev-servers` | Starting and stopping dev servers (preferably `lt dev up`), so no process is left behind; waiting for pipelines and deployments |
| `validating-changes-in-browser` | The last step before shipping: starts the app, seeds test data and walks the changes in the browser |
| `validating-ci-pipelines-locally` | Runs GitLab CI (or GitHub Actions) locally with the real image and services before the push |
| `validating-production-readiness` | The production-readiness checklist with eight pillars |
| `running-load-tests-with-k6` | k6 smoke, load and soak tests against the API |

## Updates and maintenance

| Skill | When it is used |
|---|---|
| `nest-server-updating` | Updating `@lenne.tech/nest-server` in npm mode |
| `nest-server-core-vendoring` | Projects with a vendored nest-server core in `src/core/` |
| `nuxt-extensions-core-vendoring` | Projects with a vendored nuxt-extensions core in `app/core/` |
| `ng-base-core-vendoring` | Angular apps with a vendored ng-base core |
| `maintaining-npm-packages` | Updating, auditing and cleaning up npm dependencies |
| `modernizing-toolchain` | Moving from jest, eslint and prettier to vitest, oxlint and oxfmt |
| `maintaining-lt-stack` | Maintaining and releasing the lt base repos in dependency order |
| `contributing-to-lt-framework` | Changing nest-server, nuxt-extensions or ng-base itself and testing it in a starter via `pnpm link` |
| `maintaining-ai-models` | Keeping a project's LLM models available and measured |
| `deploying-to-turboops` | Taking a fullstack monorepo live on TurboOps |

## Tickets, decisions and texts

| Skill | When it is used |
|---|---|
| `grilling-decisions` | Settles every open decision with you before the implementation starts |
| `maintaining-architecture-decisions` | Checks tickets, plans and proposals against the repository's ADRs |
| `writing-linear-comments` | Every Linear comment a command posts |
| `writing-qa-test-instructions` | Decides whether a ticket can be tested by non-developers and writes the test instructions |
| `filing-ai-proposed-tickets` | Every ticket Claude opens on its own initiative: duplicate search, Triage, label `KI-Vorschlag` |
| `rebasing-branches` | Rebasing a feature branch onto `dev` with conflict resolution |
| `unslop` | Every text a person reads, in English and German: tickets, commits, MR descriptions, docs |

## Sessions and housekeeping

| Skill | When it is used |
|---|---|
| `coordinating-peer-sessions` | Working next to other Claude Code sessions you started (see [Parallel sessions](../4.workflows/3.parallel-sessions.md)) |
| `coordinating-agent-teams` | Parallel work this session starts itself, with worktree isolation |
| `managing-agent-memory` | Whether `.claude/agent-memory/` is committed, and curating it |
| `cleaning-up-disk-space` | Freeing disk space on a developer Mac: pnpm store, caches, Docker, old `node_modules` |
| `developing-claude-plugins` | Creating and checking Claude Code plugins |
